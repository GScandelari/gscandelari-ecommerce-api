Sobre o projeto

O que é isso

Este é um projeto de portfólio — uma API de e-commerce real, com regras de negócio completas (não um CRUD de exemplo): estoque decrementado transacionalmente, máquina de estados de pedido, pagamento real em modo teste do Stripe com confirmação via webhook assinado, cancelamento e reembolso deliberados, e notificação por e-mail ao cliente.

Construído incrementalmente com TDD (testes escritos antes da implementação), cobertura de testes acima de 70% em cada serviço, CI obrigatório em toda mudança e deploy manual (nunca automático) para o projeto Firebase real, sempre em modo teste/sandbox — este projeto nunca processa dinheiro real.

A arquitetura é composta por três microsserviços independentes atrás de um API Gateway, com comunicação interna autenticada via ID token do Google — decisão deliberada para demonstrar domínio de padrões de sistemas distribuídos, não só de CRUD.

Regras de negócio (RNs)

Como funciona

Arquitetura de microsserviços

API Gateway

Firebase Hosting como porta de entrada única, roteando cada path para o serviço correto.

Orders

Dono exclusivo de produtos e pedidos. Estoque transacional, máquina de estados, cancelamento.

Payments

Toda a integração com o Stripe: PaymentIntent, webhook assinado, reembolso.

Notifications

Reage a mudanças de status via Firestore Trigger e envia e-mail — sem rota HTTP pública.

Orders e Payments se comunicam de forma síncrona via HTTP interno, autenticado com ID token assinado pelo Google — cada serviço roda sob sua própria service account de runtime, com o mínimo de permissão IAM necessária. Notifications é assíncrono e best-effort: uma falha de e-mail nunca reverte uma transição de pedido já efetivada. Ver diagrama completo →

Regras de negócio

O que a API faz

Catálogo de Produtos

CRUD completo, admin-only para escrita, validação com Zod.

Pedidos & Estoque

Criação com decremento transacional de estoque e máquina de estados completa.

Pagamento Real (modo teste)

PaymentIntent do Stripe por pedido, confirmação via webhook assinado, idempotente.

Cancelamento & Reembolso

Cancelamento pelo Cliente ou Admin conforme o estado; reembolso sempre manual e deliberado.

Notificações por E-mail

E-mail ao cliente na confirmação/cancelamento do pedido — best-effort, nunca bloqueia.

Autenticação & Autorização

Firebase Auth com custom claim admin — fonte real de verdade no backend.
